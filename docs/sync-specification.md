# 同期仕様

この文書は `chrome.storage.sync` とローカル保存の間でノートを扱う際の期待動作を定義する。

## データの役割

- ローカル保存はすべてのノートの作業コピーと復旧用バックアップを保持する。
- 同期保存は同期が有効なノートだけを保持する。
- `syncedText` は、最後に同期が成功した本文を表す。競合判定の基準として使用する。
- 同期保存の失敗によってローカル保存済みの本文を削除または巻き戻さない。

## 状態判定

ローカル本文を `localText`
リモート本文を `remoteText`
最後に同期した本文を `baseText` とする。

| ローカル変更 | リモート変更 | 結果                                   |
| ------------ | ------------ | -------------------------------------- |
| なし         | なし         | 同期済みとして維持する                 |
| あり         | なし         | ローカル本文を同期する                 |
| なし         | あり         | リモート本文をローカルへ反映する       |
| あり         | あり         | 競合として扱い、どちらも自動破棄しない |

変更判定:

```text
localChanged  = localText  != baseText
remoteChanged = remoteText != baseText
```

`baseText` が存在しない旧データは、読み込み時点の同期本文を基準値として正規化する。
安全に判定できない場合は、上書きより競合扱いを優先する。

## チャンク保存

1. 同期対象ノートをJSONへシリアライズする。
2. 単一アイテムの安全上限以内なら、単一キーに保存する。
3. 上限を超える場合はUTF-8文字単位でチャンクへ分割し、バージョン、チャンク数、合計バイト数をメタデータへ保存する。
4. すべての新しいデータを書き込んだ後、余った旧チャンクを削除する。
5. 合計容量を超える場合は同期を失敗させ、ローカル本文を維持する。

## チャンク読み込み

- メタデータのバージョンとチャンク数を検証する。
- 必要なチャンクがすべて文字列として存在することを確認する。
- 結合結果をJSONとして解析し、ノート配列のスキーマを検証する。
- 欠損、不正なJSON、不正なノート形式を空の正常データと同一視しない。
- 読み込み失敗時はローカルバックアップを維持し、同期済みデータによる上書きを行わない。

## 削除と同期解除

- 同期を無効にしたノートはローカルに残し、次回の同期保存対象から除外する。
- 同期中のノートを削除した場合、次回の同期保存から除外する。
- リモートからノートが消えた場合でも、ローカルに未同期変更があれば自動削除しない。

## 要件から導く主要テスト

- `SYNC-002`: `decode(encode(text))` が任意の有効な本文で `text` と一致する。
- `SYNC-002`: 最大値の直前、同値、直後で保存方式が正しく切り替わる。
- `SYNC-002`: チャンク欠損時にローカル本文を維持する。
- `SYNC-003`: ローカルのみ変更、リモートのみ変更、双方変更の3経路を検証する。
- `SYNC-004`: 同期再開時に差分があればユーザー選択なしで上書きしない。
- `SYNC-005`: 旧形式と現行形式から同じノートモデルを復元する。
