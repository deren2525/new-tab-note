# New Tab Note 要件定義

この文書は実装方法や画面構造ではなく、ユーザーに保証する振る舞いを定義する。
要件を変更するときは、対応するテストと同期仕様も確認する。

## ノート

### NOTE-001 ノートの永続化

ユーザーが入力したノートは自動保存され、ブラウザを再起動または再読み込みしても復元される。

受け入れ条件:

- 保存中または保存失敗によって画面上の本文を消去しない。
- 保存済みデータが不正な場合は安全に無視または復旧し、例外で画面全体を使用不能にしない。
- 旧形式の保存データは対応可能な範囲で現行形式へ正規化する。

### NOTE-002 複数ノート

ユーザーは複数のノートを作成、選択、編集、削除できる。

受け入れ条件:

- 各ノートには一意なIDがある。
- ノートを切り替えても、他のノートの本文を変更しない。
- 選択中のノートを削除した場合、残っているノートを選択する。
- 最後のノートを削除した場合、選択状態と本文を空にする。
- 存在しないノートIDに対する操作で、他のノートを変更しない。

## 同期

### SYNC-001 明示的な同期対象

同期を有効にしたノートだけを `chrome.storage.sync` に保存する。
同期を無効にしたノートはローカルに保持する。

### SYNC-002 容量制限

同期データが1アイテムの上限を超える場合は、UTF-8文字を壊さず複数アイテムへ分割する。
同期領域全体の上限を超える場合でもローカル本文を維持する。

受け入れ条件:

- 分割して保存した本文は、元の本文と完全に一致するよう復元できる。
- 日本語、絵文字、改行を含む本文を破損させない。
- 更新によってチャンク数が減った場合、不要になったチャンクを削除する。
- チャンク欠損、不正なメタデータ、不正なJSONを正常なノートとして適用しない。
- 容量超過または書き込み失敗時にローカル本文を削除しない。

### SYNC-003 同時編集

複数端末で同じノートが変更された場合、未同期の本文を通知なしに破棄しない。
詳細は [同期仕様](sync-specification.md) と [ADR-001](decisions/001-sync-conflict-policy.md) を参照する。

### SYNC-004 同期の再開

同期を無効にしている間にローカルまたはリモートの本文が変化した場合、再開前にユーザーの選択を必要とする。

### SYNC-005 互換性と復旧

単一キーへ保存する旧形式と、メタデータおよびチャンクを使う現行形式を読み込める。
同期領域のデータが消失または破損した場合、利用可能なローカルバックアップを優先して本文消失を防ぐ。

## 表示設定

### PREF-001 端末固有設定

テーマ、フォント、フィルターモード、編集・プレビュー表示、サイドメニュー状態は端末ごとに保持する。
DOM構造、CSSクラス、配置は本要件の対象外とする。

## テスト方針

- テスト名に関連する要件IDを含める。
- 保存、同期、競合、移行は純粋関数とStorage境界のテストを優先する。
- UIテストは主要操作からユースケースが呼び出されることだけを少数確認する。
- DOM構造やCSSクラスのスナップショットを仕様の代わりにしない。
- 現在の実装を追認するのではなく、この文書の受け入れ条件から期待値を決める。
